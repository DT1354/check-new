# Chrome 临时目录清理容错设计

## 问题

学校后台已经确认打卡成功后，Chrome 退出时仍可能短暂写入临时配置目录。
此时 `TemporaryDirectory.cleanup()` 偶发抛出 `Directory not empty`，异常会覆盖
已经产生的成功结果，使任务与飞书通知误报失败。

## 判定边界

- 打卡成功仍以提交后再次查询 `HAS_QD=1` 为唯一依据。
- 登录、状态查询、提交或提交后验证失败，继续按真实异常记录失败。
- 浏览器退出后的临时目录清理属于本机收尾工作，不改变学校后台结果。

## 实现

关闭浏览器进程后，最多重试五次清理临时配置目录，并采用短暂递增等待。
若仍无法删除，仅写入服务器警告日志并继续返回已经确认的业务结果。回归测试覆盖
“首次失败后成功”和“持续失败但不向任务层抛出”两种情况。
